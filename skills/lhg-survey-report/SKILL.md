# lhg-survey-report：结论"数据+解读+局限"三段式

> 目标：结论是报告的灵魂。三段式保证每条结论"有据、有话、有边界"。
> 核心纪律：**没有"局限"的结论是不完整的结论；相关不许写成因果**。

## 1. 何时使用

- `/lhg-survey:survey` 的 Phase 5 → 全程按本 skill 执行
- 统计结果有了、不知道怎么写成"人话" → 按第 3 节三段式逐条写
- 报告被质疑"结论太武断" → 检查第 4 节的局限清单

## 2. 输入与输出

- **输入**：描述统计结果 + 推断统计结果 + 图表
- **输出**：结论报告 Markdown（第 5 节结构）
- **不输出**：新的统计计算——数字都应在 lhg-survey-stats 阶段定稿

### 写报告前的检查
1. 清洗报告有了吗？（有效 n 是多少）
2. 每个推断结论都有方法名+n+p 值吗？
3. 图表标题都是结论句吗？
4. 审计 blocker 清零了吗？

## 3. 三段式写法（每条结论）

**第一段：数据**（发生了什么，只讲事实）
- 模板："女性满意度均值 4.1（n=59），男性 3.8（n=58），t 检验 p<0.05，差异显著。"
- 只写数字和方法，不解释、不引申。

**第二段：解读**（意味着什么，讲一次）
- 模板："说明女性用户对当前产品的接受度更高，可能与女性更关注 XX 功能有关。"
- "可能"不能省——解读是推测，不是事实。
- 一条数据只解读一次，不许同一个数字在报告里解读出三个意思。

**第三段：局限**（边界在哪，诚实）
- 模板："局限：样本集中在 25-35 岁（占比 70%），结论外推到全年龄段需谨慎；相关性不代表因果。"
- 没有局限的结论 = 耍流氓。审稿人/老板第一个看的就是你有没有自知之明。

### 三段式示例（完整）
> **结论 1：女性满意度显著高于男性**
> - 数据：女性均值 4.1（n=59，标准差 0.8），男性 3.8（n=58，标准差 0.9），t 检验 p=0.03。
> - 解读：女性用户对产品接受度更高，可能与问卷中女性更关注"操作便捷"有关（Q8 女性选择率高出 15 个百分点）。
> - 局限：样本男女比例人为配平 1:1，与实际用户结构（女 70%）不一致；p=0.03 处于临界，建议扩大样本后复核。

## 4. 局限清单（写不出来时对照抄）

- **样本代表性**：样本结构 vs 总体结构（如年龄/地域偏差）
- **样本量**：n<100 的结论加"样本量有限"；n<30 的不做推断
- **测量**：量表题的主观性、自陈问卷的社会期许偏差
- **方法**：用的什么检验、有没有更合适的方法没做
- **因果**：所有相关结论加"相关不代表因果"
- **时效**：数据是哪年哪月收的，结论有效期

## 5. 报告固定结构

```markdown
# 《xxx》问卷分析报告

## 1. 基本信息
问卷名称 / 回收时间 / 原始 n / 有效 n / 有效率 / 问卷渠道

## 2. 样本画像
性别/年龄/地域分布（1-2 张图）

## 3. 数据清洗说明
（贴 lhg-survey-clean 的清洗报告摘要）

## 4. 描述统计
每题一小节：数据 + 一句话解读

## 5. 交叉分析
每个分析问题一小节：方法 + 结果 + 三段式结论

## 6. 核心结论（3-5 条）
三段式，每条编号

## 7. 局限与建议
局限清单 + 下一步建议（如"扩大 40 岁以上样本后复核结论 2"）

## 附录
分析计划 JSON / 图表清单 / 原始数据说明
```

## 6. 结论的三种死法（自查）

1. **数据裸奔**：只有解读没有数据——"女性更满意"，n 呢？p 呢？
2. **解读失控**：从"相关"写到"因果"——"因为女性更细心，所以满意度高"，数据没告诉你"因为"。
3. **局限失踪**：整篇报告没有"局限"二字——读者默认你在隐瞒，信任归零。

## 7. 报告的读者视角（写给谁看）

同一份数据，给不同的人看，报告写法不一样。动笔前先定读者：

- **给老板/客户**：结论先行。第一页就是 3-5 条核心结论 + 建议，细节放后面。
  老板没时间看 20 页，电梯里 30 秒能说清的才叫结论。
- **给学术/评审**：方法先行。清洗规则、检验方法、局限要写全，可复现是底线。
- **给公众/媒体**：故事先行。一张核心图 + 一句话结论 + 数据来源，术语翻译成人话。

不管给谁看，三段式不变，变的是详略和顺序。读者错位的症状：
给老板的报告写了 5 页方法论 → 老板翻两页就扔了；给评审的报告没写局限 → 直接打回。

### 一页纸摘要（给老板的必备附件）

- 核心结论 3 条（一句话一条）+ 1 条建议，A4 一页。
- 摘要里每个数字标来源页码（如"见报告 P4"），老板追问时 3 秒翻到。
- 摘要不写方法细节，但要写有效 n 和数据时间——这是老板判断"信不信"的两个数。
- 摘要的标题就是最重要的那条结论，别写"《xxx》问卷分析报告摘要"这种废话标题。
- 摘要发出前，让没看过报告的人读一遍，能复述出 3 条结论 → 过关。
- 完整报告和一页纸摘要用同一个结论口径，数字必须一致——两处数字打架是最业余的错误。
- 摘要的建议只写 1 条：老板一次只能记住一个行动，写多了等于没写。

## 8. 常见误区（反模式）

- ❌ 结论写 20 条——读者记住 3 条就不错了，核心结论 3-5 条，其余放描述统计
- ❌ "证明了""证实了"——统计只能"支持/不支持"，不许用"证明"
- ❌ 不显著的结果不写——阴性结果进附录也比藏起来强
- ❌ 建议写"加强宣传"这种空话——建议要具体："针对 40 岁以上用户做一轮可用性测试"
- ❌ 报告里出现审计没通过的数字——blocker 不清零，报告不许发出

## 9. 自检与反馈

报告写完后：

1. 每条核心结论都是三段式吗？→ 抽查一条，缺哪段补哪段
2. 全文搜"导致""使得""证明""证实"，逐个检查→ 有因果表述就改
3. 局限写了吗？→ 没写不算做完
4. 核心结论 3-5 条吗？→ 超了就合并或降级到描述统计
5. 建议具体吗？→ "加强xx"这种删掉，换成可执行的动作

反馈渠道：以 `[QC] <一句话问题>` 为标题提交到 https://github.com/lhg-plugs/lhg-survey/issues，
正文写清"场景 → 报告问题 → 期望"。好的报告结构变体（如学术风/汇报风）也欢迎贡献。
